# ADR-0017: Compile Canonical Loadout VFX Before a Shared Cocos Runtime

- Status: Accepted for TASK-014D3
- Date: 2026-07-29

## Context

TASK-014C proved canonical loadout target resolution and semantic-event
delivery with procedural Cocos effect construction. TASK-014D1 later defined
portable authoring and exact executable sampling semantics, and TASK-014D2
proved a concrete Render Plan adapter with stronger transaction, ownership,
material, sorting and spatial guarantees. Keeping the TASK-014C hard-coded
renderer as the canonical source would leave two visual construction systems.

The read-only audit establishes this accepted chain:

```text
canonical loadout contract/resolver
→ evaluated canonical pose and prop sockets
→ Character Semantic Events evaluator
→ D1 authoring compiler
→ concrete Render Plan
→ D2 descriptor/runtime/renderer implementation
→ Creator Scene
```

The canonical loadout runtime owns loadout, pose, semantic target, Stress,
Rebuild and Exact Reset state. The event evaluator owns semantic command
timing and persistent coalescing. D1 owns parameters, curves, ticks,
particles, serialization and layer lifecycle. D2 owns typed recipe
realization, sampling consumption, renderer ownership, cleanup compensation,
blend verification, sorting, visibility, projection and spatial diagnostics.

## Decision

TASK-014D3 adds one textual canonical authoring document by combining the four
accepted D1 fixtures. A build-time generator parses and compiles it with typed
semantic and logical-resource descriptors plus closed parameter overrides.
The generated artifact is a concrete plan and the only canonical runtime VFX
data source.

The D2 production implementation becomes a shared Cocos Render Plan runtime.
The D2 minimal Scene and D3 canonical Scene import the same descriptor,
runtime state, exact sampler mirror, cleanup coordinator, renderer
host/factories, material gate, sorting allocator, spatial checks and
diagnostics. D3 contains composition and target-resolution policy only.

D3 uses a new Creator-owned Scene derived from the accepted canonical Scene
structure. It inherits the canonical resolver/pose runtime and uses TASK-014C
target bindings for actual evaluated feet, torso, active hand and prop grip.
It translates evaluator commands by typed command/lifecycle fields into the
shared concrete-plan runtime. Cue and resource names select data entries only;
they never select Cocos behavior.

Target snapshots are generation-owned. A target change cleans the affected
runtime instance before publishing the new immutable target map. Persistent
Aura remains evaluator-owned and coalesces across loops. Reset, track switch,
rebuild and disposal route through the shared transactional cleanup boundary.

## Invariants

- Runtime never parses authoring JSON, resolves bindings or samples curves
  outside the exact D1 mirror.
- Compiled plans contain no authoring parameters or engine concepts.
- Character Semantic Events and D1 public semantics are unchanged.
- No primitive, recipe, blend or lifecycle behavior dispatches from cue or
  resource name substrings.
- D2 and D3 cannot evolve separate renderer/runtime implementations.
- Primary errors and cleanup errors remain distinct; failed cleanup retains
  compensation ownership; completed destroy steps are not repeated.
- Sorting bands and transformed four-corner bounds are centrally allocated
  and measured for Normal and Transform Stress.
- TASK-014C Scene and implementation remain accepted historical production
  inputs and are neither overwritten nor regenerated by D3.

## Consequences

The canonical integration gains deterministic AI-editable authoring while
retaining the accepted loadout and semantic-event boundaries. Cocos runtime
code is larger only at the shared renderer boundary; future canonical Scenes
compose it rather than copy it. Generated plan and source mirrors require
strict closure tests and Creator metadata adds one Scene/component pair.

Authoring UI, new D1/D2 semantics, Unity/Godot adapters, production asset
generation and TASK-014D4 remain separate work.
