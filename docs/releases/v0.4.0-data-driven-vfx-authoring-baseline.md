## Release positioning

v0.4.0 records the accepted data-driven VFX authoring path from a portable
text document to the canonical Cocos full-loadout runtime:

```text
VFX Authoring Document
→ deterministic compiler
→ concrete Render Plan
→ shared Cocos adapter/runtime
→ canonical full-loadout integration
→ Creator lifecycle/spatial/visual acceptance
```

This is a prerelease framework baseline, not a finished commercial tool.
Its procedural/reference effects prove deterministic compilation, typed
runtime realization, lifecycle ownership, spatial safety, and Creator
integration. They do not claim production VFX art quality.

This document records the accepted and published source baseline. Publication
did not change the accepted capability bytes or start TASK-014D4.

## D1 — engine-neutral authoring and deterministic compilation

TASK-014D1 adds the standalone `@gameai/vfx-authoring` package and
`schemas/vfx-cue-authoring.schema.json`. An authoring document references
semantic cue IDs and logical resources without storing Cocos, Unity, Godot,
Scene, node, material, or engine-path data.

The fail-closed compiler:

- validates closed cue, layer, resource, lifecycle, binding, curve, timing,
  particle, randomness, and budget surfaces;
- resolves typed parameter defaults and overrides into concrete layer values,
  so parameter and binding names do not enter the published plan;
- normalizes cue, layer, object-key, and serialized output order;
- uses a 12-decimal canonical integer-tick time model rather than epsilon or
  floating-point quotient equality;
- defines linear, clamped curves with exact endpoints and rest-relative
  transform, color, opacity, scale, and rotation composition;
- fixes particle schedules, lifetime fit, seed handling, and
  `xorshift32-v1` random samples; and
- enforces explicit limits on cues, layers, parameters, curves, particles,
  commands, and serialized output before returning a complete concrete
  Render Plan.

Repeated compilation, input permutations, and locale changes produce
byte-identical plans. Invalid input produces diagnostics and no partial plan.
Character Semantic Events continues to own cue timing and lifecycle commands;
D1 owns visual authoring, compilation, canonical sampling, and concrete layer
semantics.

## D2 — shared Cocos Render Plan adapter/runtime

TASK-014D2 consumes concrete Render Plans only. Runtime code does not parse
authoring JSON, resolve parameters, infer behavior from cue/resource names,
or implement a second timing/sampling model.

The shared Cocos boundary provides:

- exhaustive typed dispatch for sprite-quad, ring, ribbon, and burst-particle
  primitives;
- typed textured-sprite, procedural-ring, procedural-ribbon, and particle
  recipes with explicit alpha, additive, screen, and multiply blend state;
- exact reuse of the D1 sampler and portable boundary vectors;
- deterministic global sorting independent of activation order;
- nested-transform projection and transformed four-corner viewport bounds;
- pending/active/removed visibility and exact renderer/instance/descriptor
  ownership;
- one all-steps transactional cleanup coordinator that preserves the first
  business error, records ordered cleanup errors separately, retains failed
  compensation ownership, and never repeats successful destroy steps; and
- symmetric setup failure, terminal failure, target invalidation, rebuild,
  retry, disable, destroy, and Exact Reset behavior.

After compensation, root/input/owner/material/node ownership reaches
`0/0/0/0/0`; the same component can retry to `READY` with root/input `1/1`.
Exact Reset keeps the live component root/input and removes active VFX
ownership before restoring stopped time zero.

## D3 — canonical full-loadout integration

TASK-014D3 compiles one canonical authoring document before runtime and makes
the shared D2 implementation the only canonical Cocos VFX execution path.
The runtime composes:

- all 12 canonical membership/prop loadout states;
- Rest, Walk, Wave, Prop Swing, and Integration Stress clips;
- left/right foot, torso, active hand, and prop-grip world targets;
- atomic loadout, prop, clip, and target rebind;
- alternating Footstep Dust;
- Hand Trail and Tool Trail;
- one persistent, coalesced Aura instance; and
- the four-layer Combined reference.

Target invalidation removes the old renderer before publishing a replacement
target map. Pause/Resume, Transform Stress, Debug, two consecutive rebuilds,
post-rebuild VFX, and Exact Reset retain one root/input and zero duplicate,
stale, leaked, mismatched, non-finite, viewport, or cleanup failures.

## Creator lifecycle, fault, spatial, and visual acceptance

Creator 3.8.8 exercises the actual component and parent build paths:

- the real `onDisable` then `onDestroy` callback sequence performs ordinary
  teardown once, then dispose-only lifecycle finalization, ending with both
  readiness and lifecycle `DISPOSED`;
- eight failures before runtime publication cover base, attachment, prop,
  overlay, Graphics, Graphics Sorting2D, HUD, and HUD Sorting2D creation;
- every early partial build compensates to root/input/owner/material/node
  `0/0/0/0/0`, then retries the same component to `READY` `1/1`;
- the complete Creator fault matrix passes 25/25, including 16 cleanup entry
  cases, eight early-build cases, and the actual disable/destroy callback
  gate; and
- the complete live Preview matrix covers all loadouts, targets, effects,
  stress, rebuild, Reset, clean hold, and clean Creator/Preview consoles.

The separate 70-case coordinator matrix is synthetic transaction coverage;
real component and parent claims come from the Creator gates above. Accepted
visual evidence verifies Dust, Hand/Tool Trail, Aura, Combined, target
rebind, consecutive rebuilds, post-rebuild Trail, Exact Reset, and a stable
clean hold.

## Compatibility and limitations

| Surface | v0.4.0 status |
| --- | --- |
| Engine-neutral VFX authoring schema/compiler | Implemented and verified |
| Deterministic concrete Render Plan and exact sampler | Implemented and verified |
| Shared Cocos Render Plan adapter/runtime | Implemented and verified |
| Canonical 12-state full-loadout VFX integration | Implemented and verified |
| Cocos Creator 3.8.8 on validated macOS environment | Implemented and verified |
| Audio playback and gameplay execution | Not implemented |
| Unity runtime adapter | Not implemented or verified |
| Godot runtime adapter | Not implemented or verified |
| Windows environment | Not verified |
| Production VFX art | Not provided |
| Original Red Cap production reconstruction | Deferred |
| AI asset generation and automatic fitting | Not implemented |
| Complete production editor/authoring UI | Not implemented |
| TASK-014D4 | Not started |

The current effects are procedural/reference implementations. Engine-neutral
data and adapters designed for portability do not constitute Unity, Godot, or
Windows runtime acceptance. Typed audio/gameplay semantic events still have
no playback, hitbox, damage, or signal consumer. Red Cap reconstruction,
AI-generated production assets, automatic fitting, and a complete editor UI
remain separate future capabilities.
