## Release positioning

v0.5.0 establishes the first accepted GameAI Pipeline baseline that carries a
reviewed production-character source through deterministic layered
construction, jointed motion, semantic VFX, shared Cocos execution, and live
Creator acceptance:

```text
source authority and asset intake
→ deterministic layered asset generation
→ production character joint hierarchy
→ Rest / Idle / Walk / Wave runtime animation
→ semantic events and concrete VFX Render Plans
→ shared Cocos renderer/runtime
→ Creator lifecycle, rebuild, reset and spatial validation
→ production vertical-slice acceptance
```

This is a **Production Character Vertical Slice Baseline**. It is a
prerelease framework checkpoint, not a complete commercial game, a universal
art-production system, or a claim that every engine and host environment is
supported.

## Source authority and asset intake

PROGRAM-015 uses the accepted `red-cap-production-v1` source pack. The
character master is the sole authority for final visible pixels. The parts
sheet is limited to identification, structure, boundary, and manual audit;
the joint supplement is limited to declared hidden shoulder, elbow, wrist,
hip, knee, and ankle connectors.

The project-owner-reviewed assertion records source, modification, commercial
use, repository inclusion, and redistribution boundaries. It is bound to
provenance SHA-256
`55d350c9e44a38c8bef6d3f6b0eb0654caa1bb846c491dd7c547c71e3a862758`.
The rights assertion SHA-256 is
`335cef8824d574c4999492ae32201c79eb76683a78c342e1ae23696a85cc45f4`.
This release does not alter, supplement, infer, or reinterpret either record.

Deterministic generation publishes the accepted layered parts, atlas,
reconstruction reports, motion documents, semantic events, showcase inputs,
concrete Render Plan, and Cocos mirrors from tracked authority. A clean
tracked-files-only checkout does not require Creator cache, ignored intake,
local recordings, or machine-specific paths.

## Production character and motion

The Red Cap runtime uses a 19-part hierarchy:

`pelvis`, `torso`, `head`, `hair`, `cap`, `bandana`, `pouch`,
`upper-arm-left`, `upper-arm-right`, `forearm-left`, `forearm-right`,
`hand-left`, `hand-right`, `thigh-left`, `thigh-right`, `shin-left`,
`shin-right`, `foot-left`, and `foot-right`.

The bounded accepted clip set is:

- Rest;
- Idle;
- Walk with real alternating left/right foot contact; and
- Wave with visible arm articulation and a joint-following left-hand target.

The runtime validates planted-foot contact/sliding and hand target/socket
error from the evaluated hierarchy. It does not add IK, retargeting,
animation blending, root motion, cloth, mesh deformation, or automatic
fitting.

## Semantic events, VFX, and shared runtime

PROGRAM-015 reuses the accepted Character Semantic Events and data-driven VFX
surfaces:

- alternating left/right-foot Dust one-shots during Walk;
- left-hand Trail during Wave;
- torso Aura during the showcase sequence; and
- scene-specific authoring compiled into concrete Render Plans consumed by
  the shared Cocos renderer/runtime.

The engine-neutral event and authoring layers do not store Cocos node,
resource, Scene, or display-name fallback behavior. Target namespaces for
production-lite and Red Cap are disjoint. The VFX host owns renderer
lifecycle, sorting, target following, cleanup, and Exact Reset through the
accepted shared runtime.

## Infrastructure stability

CI explicitly installs and audits both `ffmpeg` and `ffprobe` before
workspace verification.

The Sharp full-loadout regression was repaired structurally in PR #24:

- tracked inputs remain read-only;
- each test/generator uses complete isolated input and output roots;
- PNG bytes are written completely to a unique same-directory temporary file
  before atomic rename;
- readers observe an old complete file or a new complete file, never an empty
  or partial Buffer;
- deterministic concurrency regression preserves real writer/reader overlap;
  and
- no retry, sleep, suite serialization, ignored error, repository fallback,
  or reduced concurrency masks the behavior.

## Local Experimental Asset Mode

`artifacts/experimental/<experiment-id>/` is the only standard Local
Experimental Asset root. Everything below it—including source inputs,
generated derivatives, temporary Scenes, recordings, extracted frames, and
analysis—remains ignored, untracked, and local-only.

Local experiments may support Creator, animation, VFX, recording, and
framebuffer work without repository publication records. That exception does
not assert ownership, commercial-use permission, or redistribution
permission. The material is:

> disposable local-only experimental input, not approved for repository
> publication or redistribution

Before an input or direct derivative is prepared for staging, pushing,
review, or publication, it becomes a Repository Candidate and must pass the
complete rights/provenance, privacy, security, redistribution, dependency,
generated-closure, binary/media, and scope audit. Clean tracked-only CI must
never depend on ignored experimental material.
