## Release positioning

v0.3.0 is the first accepted GameAI Pipeline baseline in which one
engine-neutral semantic event stream drives deterministic visible effects on
a canonical composable character across loadout, prop, animation, transform,
rebuild, and Exact Reset boundaries.

This is a prerelease framework baseline, not a finished commercial tool.
Procedural effects prove contracts, delivery, lifecycle, spatial behavior,
and cleanup; they are not production-ready final VFX art.

The original documentation closeout did not create or move the `v0.3.0` tag,
publish a GitHub Release, or start TASK-014D. The annotated tag and prerelease
were subsequently published without changing this historical capability
baseline.

## Authoritative architecture

```text
Character Semantic Events contract
→ deterministic evaluator
→ canonical resolved character loadout
→ evaluated semantic target/socket registry
→ Cocos Semantic VFX Adapter
→ renderer/cue registry
→ Creator runtime
```

The contract and evaluator remain engine neutral. The loadout resolver owns
character membership and global layer state. The evaluated semantic-target
registry maps stable event targets to the current resolved pose and prop
state. The Cocos adapter consumes evaluator commands, and the renderer/cue
registry owns Cocos-only procedural implementations and renderer lifecycle.

No Cocos type, resource UUID, Scene identity, renderer class, or runtime node
is stored in the engine-neutral contract.

## Engine-neutral semantic events

Character Semantic Events 1.0 supports three typed event kinds:

- `vfx`: names a validated VFX cue and lifecycle intent;
- `audio`: carries a typed semantic audio contract, including gain and pitch;
  and
- `gameplay`: carries typed signal or window-open/window-close intent.

The schema, parser, semantic validation, deterministic diagnostics, textual
fixtures, and evaluator cover all three kinds. An unrestricted arbitrary
payload is not supported.

The implemented runtime consumer in v0.3.0 is **Cocos VFX only**. Audio events
and gameplay events remain validated, counted delivery contracts; there is no
audio playback consumer and no gameplay hitbox, damage, or signal consumer.

## Deterministic evaluator and lifecycle

Normal forward evaluation uses `(previousTime, currentTime]` and orders
authored events by `timeSeconds`, `order`, and `eventId`. Skipped frames and
bounded loop crossings are enumerated deterministically.

Accepted lifecycle behavior:

- one-shot events emit at each authored crossing;
- looping VFX start once per crossed cycle and stop at their authored
  duration;
- persistent VFX coalesce to one logical active instance per track/event;
- the concrete persistent instance ID retains its first actual start cycle;
- Pause/Resume preserves active instances without duplicate starts;
- track switching stops old-track instances exactly once;
- Exact Reset stops active instances, clears progress, and returns to stopped
  time zero;
- rebuild and disposal clean each active instance exactly once; and
- playback after cleanup may start the event again.

Reverse playback and arbitrary seeking remain explicitly rejected.
Advancement rejects non-finite or over-budget progress before state mutation.

## Canonical full-loadout integration

The canonical resolver-derived matrix contains four membership combinations
crossed with three prop states:

| Character membership | No prop | Left prop | Right prop |
| --- | --- | --- | --- |
| Base | Supported | Supported | Supported |
| Accessories | Supported | Supported | Supported |
| Garment | Supported | Supported | Supported |
| Garment + accessories | Supported | Supported | Supported |

The evaluated semantic-target registry supports:

- left-foot target;
- right-foot target;
- torso/body target; and
- active hand/tool target for no-prop, left-prop, and right-prop states.

Loadout or prop changes rebuild an immutable target snapshot from the new
canonical plan and evaluated pose. Active renderers retain stable logical
target IDs, never raw stale node ownership. Valid targets are reprojected
immediately; invalidated targets stop exactly once. There is no filename,
Canvas-coordinate, opposite-hand, or Scene-name fallback.

## Accepted Cocos placeholder effects

- **Footstep Dust**: alternating one-shot left/right-foot bursts
- **Wave/Prop Trail**: looping Trail following the active hand or prop tool
- **Persistent Aura**: one coalesced torso instance across at least six loops
  and Pause/Resume

The reference implementation uses deterministic procedural Cocos geometry.
It contains no production effect assets and makes no final-art-quality claim.

## Runtime guarantees

At every accepted stable state the Cocos runtime maintains:

- one runtime root;
- one input handler after readiness;
- zero duplicate starts;
- zero unknown stops;
- zero leaked instances;
- zero stale semantic targets or renderers;
- finite transforms and projections;
- viewport-safe rendering at the 1280×720 acceptance resolution;
- deterministic generation and symmetric rebuild/disposal cleanup; and
- Exact Reset to the canonical garment-and-accessories/no-prop Rest state,
  `STOPPED`, `0.00`, Transform Stress OFF, VFX/target debug OFF, and zero
  active effects.

Global renderer ordering uses the accepted Cocos sorting boundary. Position,
rotation, and scale follow policies are applied independently. Transform
Stress composes outside the authored character hierarchy without changing the
engine-neutral baseline.

## Current limitations

- Procedural placeholder VFX rather than production art
- No actual audio playback consumer
- No gameplay hitbox, damage, or signal consumer
- No reverse playback
- No arbitrary seek
- No network synchronization or rollback
- No VFX editor or authoring UI
- No automatic effect fitting
- No Unity adapter
- No Godot adapter
- Windows not verified
- Original Red Cap production reconstruction deferred
- Rigid sprites, authored character fitting/grips, in-place motion, and no
  general IK, blending, cloth, mesh deformation, or root-motion system

The baseline does not claim production-ready final VFX quality,
audio/gameplay execution, cross-engine runtime support, Windows support,
automatic AI asset generation, or complete editor tooling.

## Next recommended capability

TASK-014D — Data-Driven Production VFX Cue Authoring is the proposed next
feature direction. Its future goal is to:

- replace hard-coded procedural effect construction with a validated,
  engine-neutral authoring description;
- allow AI to generate or modify VFX cue data;
- support reusable cue presets;
- preview cue timing, socket binding, transforms, color, duration, and layers;
- compile engine-neutral cue descriptions into Cocos renderer plans;
- retain Unity/Godot adapter compatibility; and
- keep production-quality asset generation separate from runtime logic.

TASK-014D is not implemented or started by this release-documentation
baseline. Later roadmap work also includes audio and gameplay consumers,
animation authoring, production editor UI, automatic cutting/fitting, Unity,
Godot, Windows verification, and original Red Cap reconstruction.
