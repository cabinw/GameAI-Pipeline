## Release objective

Freeze a durable, reproducible reference for composing a rigid 2D base
character, layered head accessories, a multi-part garment, and an authored
one-handed prop through engine-neutral contracts and one canonical Cocos
adapter.

This document records accepted behavior. It does not create the `v0.2.0` tag
or GitHub Release and does not start TASK-014.

## Architecture overview

```text
versioned engine-neutral contracts
→ parse and semantic validation
→ resolveCharacterLoadout
→ immutable resolved rig, attachments, states, and global layers
→ deterministic generated R6-compatible Cocos plan
→ canonical V2 adapter
→ Creator-owned Scene and runtime nodes
```

The complete 12-state matrix lives in the tracked engine-neutral loadout
contract. `resolveCharacterLoadout` rejects invalid or ambiguous semantics
before generation. The Cocos plan is derived output and cannot independently
define state membership.

The canonical adapter owns only engine responsibilities: terminal resource
loading, lifecycle/readiness, node construction, semantic input dispatch,
global `Sorting2D`, HUD/debug rendering, world-to-overlay-local projection,
and runtime measurements.

## Supported contracts and state matrix

The baseline supports:

- Character Rig and Rig Layout 1.0 contracts;
- Rig Animation 1.0 semantic clips;
- optional Attachment Layout 1.0 slots, transforms, roles, wearable sets,
  seams, prop states, grip anchors, and hand overlays; and
- the engine-neutral composable loadout contract and resolver.

The canonical state matrix is:

| Character membership | No prop | Left prop | Right prop |
| --- | --- | --- | --- |
| Base | Supported | Supported | Supported |
| Accessories | Supported | Supported | Supported |
| Garment | Supported | Supported | Supported |
| Garment + accessories | Supported | Supported | Supported |

Each of the 12 state IDs is unique and resolves exact attachment membership.
The runtime uses 17 base parts, 3 head-accessory parts, 11 garment parts, and
4 prop/overlay attachments across a 35-resource manifest.

## Accepted runtime behavior

- Rest, Wave, Prop Swing, and Integration Stress are exposed by explicit
  semantic IDs in canonical V2.
- Pause freezes the current pose and time; Resume continues it.
- Manifest PASS precedes construction.
- Keyboard input becomes active only after resources, nodes, playback, Exact
  Reset, and lifecycle READY.
- Rebuild, failure, disable, and destroy leave zero stale input handlers.
- Global production, debug, and HUD sorting ranges do not overlap.
- Joint, Skeleton, accessory socket, garment seam, and prop grip diagnostics
  use current runtime world transforms.
- Debug projection converts real world targets into
  `DebugOverlayRoot`-local geometry without character or Canvas offsets.

## Exact Reset

Exact Reset returns canonical V2 to:

- authored Rest pose;
- playback `STOPPED`;
- time `0.00`;
- garment and accessories enabled;
- no prop;
- Transform Stress OFF;
- Debug OFF; and
- no residual debug geometry or duplicate runtime nodes.

From a clean tracked checkout:

```bash
pnpm install --frozen-lockfile
CI=true pnpm verify
git diff --exit-code
git status --porcelain
```

Normal generation excludes the superseded monolith. Its deterministic
historical check remains available only through:

```bash
pnpm --filter gameai-character-rig-builder legacy:verify-task013-provenance
```

Do not depend on Creator `temp`, `library`, `local`, ignored build output,
absolute machine paths, or evidence videos.

## Migration from the superseded TASK-013 Scene

Do not use
`cocos/projects/character-rig-builder-mvp/assets/composable-full-loadout-reference.scene`
as a production entry point. It predates the accepted lifecycle, readiness,
resource, input, sorting, projection, and runtime-spatial boundaries.

Consumers should:

1. target the canonical V2 Scene and adapter ID listed above;
2. keep authored semantics in engine-neutral contracts;
3. resolve loadout state before crossing the Cocos boundary;
4. use semantic action and clip IDs rather than array indices or display
   names; and
5. retain the old Scene only when reproducing historical provenance.

## Known limitations

- Rigid sprite articulation with authored fitting and grip positions.
- Garment seam validation uses transformed AABBs, not oriented polygons,
  deformation, or cloth simulation.
- In-place motion; no root motion or foot locking.
- No IK, automatic fitting, mesh deformation, animation blending, prop
  physics, combat, VFX runtime, Unity adapter, Godot adapter, Windows
  validation, production editor UI, or original Red Cap production
  reconstruction.
